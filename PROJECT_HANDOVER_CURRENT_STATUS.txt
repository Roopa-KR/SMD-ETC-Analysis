--------------------------------

VERIFIED: The application answers: based on work still open and picking productivity observed so far, will each outbound truck's required picking finish before its pick cutoff?

4.2 Exact baseline formulas
---------------------------

For snapshot T and work type w:

  TOTALTIMEINHRS = SUM(LM005S1.TOTALTIMEINSEC) / 3600

  TOTALLINES = count of completed TI102 rows at snapshot
               + count of TI102C rows with MOVED_TO_C_AT <= T,
               filtered to analysis date/client/warehouse/status 3

  TOTALPIECES = analogous sum of PROCESSEDQTY

  RESOURCES = COUNT(DISTINCT RESOURCENAME where WIPIND='Y')

  PER_PERSON_RATE = TOTALLINES / TOTALTIMEINHRS

  ACTUALRATELINES = PER_PERSON_RATE * RESOURCES

  OPENLINES = count of open TI102 rows with OPENQTY > 0
  OPENQTY = sum of OPENQTY

  ETCLINES hours = OPENLINES / ACTUALRATELINES
  ETCPIECES hours = OPENQTY / ACTUALRATEPIECES

Missing/fallback: rates are None when observed hours or resources are zero; per-person rate is None when hours are zero or no completed lines exist; ETC is None when open work exists without a positive rate.

4.3 Truck ownership, deadline and queue
---------------------------------------

  effective truck at T = ORIGINAL_SHIPMENTID before MOVED_AT,
                         otherwise final SHIPMENTID

  effective departure at T = ORIGINAL_DEPARTURE before DEPARTURE_CHANGED_AT,
                             otherwise DEPARTURE_TIME

  PICK_CUTOFF = effective departure - LOADING_MINUTES / 1440

Active synthesized schedule rule:
  unrounded cutoff = route's last release + ORDER_LEAD_MINUTES (60)
  cutoff = round upward to the next 15-minute boundary
  departure = cutoff + LOADING_MINUTES (30)
  SH0908-1072 coverage scenario is one labeled 15-minute exception.

  OPEN_LINES(s,w,T) = open item lines on truck s/work type w at T

  LINES_AHEAD(s,w,T) = sum of open lines in w for every truck whose
                       cutoff <= truck s cutoff, including s

4.4 Work-type ETC, cutoff and staffing
--------------------------------------

  WT_ETC days = LINES_AHEAD / ACTUALRATELINES / 24
  WT_READY_TIME = T + WT_ETC

Status for required open work:
  if T >= cutoff                       -> NO - CUTOFF PASSED
  else if no positive rate             -> UNKNOWN - NO RATE
  else if WT_READY_TIME <= cutoff       -> YES / ON TIME
  else                                  -> NO / AT RISK

  OPERATORS_NEEDED = CEILING(
      LINES_AHEAD / (PER_PERSON_RATE * hours_to_cutoff) - 1e-9)

  ADDITIONAL_OPERATORS = MAX(0, OPERATORS_NEEDED - RESOURCES)

These formulas are implemented and baseline-parity tested. Operator need is only calculated for an ordinary miss before cutoff; no-rate cases return explanatory text.

4.5 Truck ETC and lifecycle
---------------------------

  TRUCK_ETC = maximum required WT_ETC
  BOTTLENECK = work type producing the maximum; if any required work type has
               no rate, truck ETC is unknown and the no-rate area is named
  READY_TIME = T + TRUCK_ETC
  SLACK = PICK_CUTOFF - READY_TIME

Truck status precedence:
  1. departed: DEPARTED COMPLETE or DEPARTED - n LINES LEFT BEHIND
  2. no released/picked work: NO WORK RELEASED YET
  3. zero open work: ALL PICKED
  4. snapshot at/after cutoff with open work: PICK CUTOFF PASSED - LATE
  5. required rate unavailable: NO RATE
  6. ready <= cutoff: ON TIME; otherwise AT RISK

Missed lines at departure count released lines not picked by the departure event and remain frozen thereafter. Slack minute rounding is Excel half-away-from-zero. Display duration reproduces Excel TEXT("[h]:mm") by rounding to a second and then whole minutes. Time comparisons tolerate 1e-9 day.

4.6 Uncertainty/planning calculation
------------------------------------

For each operator/work type by T:
  operator pace = completed lines by T / LM005S1 hours in that work type

For a work type with a positive point team rate:
  observed_team_rates = current RESOURCES * each positive observed operator pace
  RATE_LOW = minimum(point team rate and observed_team_rates)
  RATE_HIGH = maximum(point team rate and observed_team_rates)
  WT_ETC_LOW = LINES_AHEAD / RATE_HIGH / 24
  WT_ETC_HIGH = LINES_AHEAD / RATE_LOW / 24

Planning status uses WT_ETC_HIGH (the slower bound). The point team rate is included in the envelope. With no operator-level variation evidence, the range equals the point estimate. This is implemented/tested but is explicitly not statistical confidence and does not cover unmeasured delays.

4.7 Existing-operator reallocation
----------------------------------

Candidate prerequisites:
  - active WIPIND Y operator on a different work type;
  - not already used in another move at that snapshot;
  - measurable source pace when source has open work;
  - destination familiarity from actual destination completions or explicitly
    simulated OPERATOR_EXPERIENCE;
  - defensible destination contribution;
  - every open source truck remains on time at point and conservative rates.

Contribution:
  actual history -> completed destination lines / destination labor hours
  simulated familiarity -> MIN(actual source pace,
                               actual destination PER_PERSON_RATE)

After a proposed move:
  DEST_RATE_AFTER = current destination team rate + destination contribution
  SOURCE_RATE_AFTER = current source team rate - operator source pace
  source conservative rate is also reduced using the observed source floor
  destination conservative rate adds a bounded contribution
  ETC/ready/slack/status/resources are recalculated on both sides

Selection is iterative and prefers a move that makes the destination safe, then less source priority work, more source slack and stronger conservative destination contribution. It stops only when all originally at-risk destination rows meet both point and conservative cutoff or no safe candidate remains.

Implemented/tested: no logged-in resources, logged-in but no positive observed rate, cutoff already passed, no work released, all picked, departed miss freezing, departure changes announced mid-day, moved orders, cancelled/non-open lines, missing familiarity, unsafe source removal, exact cutoff equality and exact-integer staffing rounding.

Not fully modeled: multi-day/timezone behavior, breaks, travel, congestion, equipment, replenishment, certification, transfer/setup delay, pieces/cube/weight constraints, actual staging/loading dependency and business-defined minimum source buffer.
